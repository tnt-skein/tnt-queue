# tnt-queue

Надёжная очередь заданий Tarantool: сообщение лежит в спейсе и переживает
перезапуск узла, а работники на файберах этого же узла берут его
и исполняют обработчик. Подтверждение — то, что вернул обработчик;
отправка в транзакции `box` — её часть, и откат уносит сообщение.
Работа внутри — рок `queue` 1.5.0 с драйвером `utubettl`.

```lua
local queue = require('tnt.queue')

local mail = queue.declare('mail', { ttr = 30 })

mail:consume(function(message)
    local ok, reason = deliver(message.body)

    if not ok then
        return nil, reason                       -- повтор с отсрочкой, потом зарыть
    end
end, { workers = 2 })

local sent, err = mail:send({ to = 'a@example.org' })   -- ULID либо nil, err
```

Зависимости: рок `queue` 1.5.0-1 с `rocks.tarantool.org` (очередь
в спейсах), `tnt-message` (общая часть договора очереди: конверт, проверка
настроек и тела, приговор обработчику, область обработчика, крюки и ряды
`message_*`: отправлено, отказы, итог обработки, ожидание, глубина),
`tnt-must` (проверки аргументов), `tnt-clock` (время зарытого), `tnt-id`
(опознаватель чужой задачи), `tnt-log` (журнал), `tnt-storage` (отказ
`TntStorageFailure`) и `tnt-external` (подмена рока, сна и признаков узла
в проверках).

## Зачем

Работу, которую нельзя делать внутри запроса, ставят в очередь, и очередь
в спейсе даёт главное: «сохранили заказ и поставили письмо» — одна
транзакция `box`, без ящика исходящих. Рок `queue` держит сроки,
приоритет и ключ порядка, но в десятке мест молча теряет либо отказывает
не парой. Пакет закрывает это и делает пять вещей:

- **Подтверждение — итог обработчика**: значение подтверждает,
  `nil, err` возвращает сообщение с отсрочкой, последняя попытка
  и `err.retriable == false` зарывают его.
- **Зарытые живут в своём спейсе `<имя>_dead`** и не исчезают по сроку
  жизни; `kick` возвращает их на выдачу.
- **Отправка в транзакции — её часть**, а с `atomic` запись обработчика
  и подтверждение фиксируются вместе.
- **Контекст едет с сообщением**: опознаватель запроса отправителя
  приходит в обработчик заголовком.
- **Крюки отправки и обработки** дают трассу и замеры, не делая пакет
  зависимым от трассировщика.

Отказ — пара `nil, err`, а не голый `nil` и исключение; рок грузится
лениво и только на узле для записи, а работник на узле для чтения ждёт
записи, а не крутит пустое взятие. Гарантия — хотя бы раз: повтор
отсекает получатель по опознавателю сообщения.

## Установка

```sh
tt rocks install tnt-queue --server=https://tnt-skein.github.io/rocks
```

Рок `queue` приходит с `rocks.tarantool.org` — сервера роков Tarantool
по умолчанию.

Или из исходников:

```sh
git clone https://github.com/tnt-skein/tnt-queue.git
cd tnt-queue && tt rocks make
```

## Как пользоваться

| Вызов | Что делает |
|---|---|
| `queue.declare(name, opts)` | объявляет очередь; настройки — `ttr`, `shape`; второе объявление имени отдаёт ту же очередь, с другими настройками — исключение |
| `queue.reset()` | забывает объявления и останавливает их получателей — для проверок и перечитывания кода |
| `queue:send(body, opts)` | отправляет сообщение и отдаёт его ULID; настройки — `headers`, `key`, `delay`, `ttl`, `priority`, `id`, `timeout` |
| `queue:consume(handler, opts)` | заводит работников; настройки — `workers`, `max_attempts`, `backoff`, `atomic` |
| `consumer:stop()` | перестаёт брать новые сообщения; взятое дорабатывается |
| `queue:kick(count)` | возвращает зарытые на выдачу со счётом выдач с нуля |
| `queue:touch(message, seconds)` | продлевает `ttr` сообщения в работе у этого файбера |
| `queue:status()` | состояние рока, счётчики, глубина, работники, крюки |
| `queue.hook(name, hook)`, `queue.hooks()` | ставит, заменяет или снимает крюк; имена крюков по порядку |
| `queue.features` | что очередь умеет: всё — `delay`, `ttl`, `ttr`, `touch`, `priority`, `key`, `transactional`, `atomic` |

На узле для чтения и в окне смены ведущего очередь отказывает
`unreachable` (`TntStorageFailure` из `tnt-storage`, `retriable = true`).
Незнакомая настройка и тело не из простых данных — исключение на строке
вызывающего:

```lua
mail:send('тело', { priorty = 1 })
--> error: настройки отправки: ключа «priorty» нет, есть delay, headers, id,
--> key, priority, timeout, ttl
```

## Проверки

```sh
make deps          # luatest, luacheck, luacov с cluacov, рок queue и зависимости пакета в .rocks
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants из PATH, порог 100 % убитых
```

Покрытие строк — 100 %, убитых мутантов — 100 % (58 проверок,
254 мутанта в пяти модулях).
Работа внутри чужая, поэтому труба, сроки,
ключ и возврат проверяются против настоящего рока: 31 проверка поднимает
временный узел Tarantool — очередь целиком, узел для чтения и отказы
`broken` и `conflict`. Работник проверяется в процессе проверок,
а конверт, приговор обработчику и крюки — в `tnt-message`.
